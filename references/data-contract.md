# 数据契约

## 实际目录

```text
<输出目录>/
├── build/
│   └── <run_id>/
│       ├── raw/
│       │   └── <企业名>.json       # 本次抓取的企业事实
│       ├── raw_home/
│       │   └── <企业名>/            # 用户资料图 + 官网图暂存（用户图 user_ 前缀）
│       ├── deliverable/
│       │   └── <企业名>/            # 渲染后的交付文件
│       ├── en.json                 # 英文层：自动翻译草稿，可被 --en 覆盖
│       ├── 英文补译清单.json        # 英文缺口清单；存在时才生成
│       ├── 视觉核对.json            # 视觉核对结论：图片/文档/产品清单（逐张，无类别继承）
│       ├── review/                  # 拼版图、缩略图核对表、视觉核对.log
│       ├── 汇总.xlsx
│       ├── 官网复核结果.json        # 跳过企业及原因；存在跳过项时生成
│       ├── gates.json
│       ├── gates.log
│       └── manifest.json
├── 官网候选复核表.xlsx              # --discover-only 生成，决定/自定义官网的复核入口
├── deliverable/                    # 门禁通过后的发布副本
└── 原始资料备份/                    # 用户提交的原始资料原件，保留原目录结构（可用 --backup-dir 改位置）
```

企业名称用于当前版本的目录名和 JSON 键。文件名会清理 Windows 不允许的字符；特殊字符导致重名时，需要用户在 Excel 中先区分企业名称。

## 输入 Excel

最低字段：

| 列 | 必填 | 说明 |
|---|---|---|
| `企业名称` | 是 | 也接受 `公司名称`、`单位名称`、`名称` |
| `官网` | 否 | 也接受 `网址`、`网站`、`官网地址` |

## 企业 raw JSON

本地流水线写入的关键字段：

```jsonc
{
  "名称": "示例科技有限公司",
  "官网": "https://example.com",
  "置信度": "用户提供",
  "产业": "食品",
  "规模": "",
  "主要业务": "",
  "地址": "",
  "核心产品": "产品A、产品B",
  "logo": [
    {
      "file": "01_logo.png",
      "alt": "logo",
      "url": "https://example.com/logo.png",
      "from": "https://example.com/",
      "wh": "300x80"
    }
  ],
  "product": [],
  "cert": [],
  "factory": [],
  "pages": [
    {"cat": "home", "url": "https://example.com/", "title": "示例科技"}
  ],
  "products": ["产品A", "产品B"],
  "product_details": {
    "产品A": "从官网产品卡片提取的中文详情，不含“查看详情”"
  },
  "intro_paragraphs": ["段1", "段2", "段3"],
  "about_text": "",
  "product_text": "",
  "home_text": "",
  "errors": [],
  "status": "ok",
  "状态原因": "",
  "资料来源": "D:\\path\\企业原始资料",
  "资料备注": "用户资料：抽取文档 2 份、抽到表格 1 份、未归类 1 项"
}
```

`资料来源` / `资料备注` 仅在通过 `--resources` 提供资料时出现。用户资料图的记录形如 `{"file": "user_xxx.jpg", "alt": "...", "url": "", "from": "照片/xxx.jpg", "wh": "", "source": "用户资料"}`——`url` 为空、`from` 记录相对原始路径、`source` 为 `用户资料`，与官网图区分；`gate_image_provenance` 对用户资料图跳过官网同域校验，视觉核对按资料优先直通，但一旦显式标“不符”仍会阻断。交付五文件夹内只含图片，Word/Excel/PDF/PPT 等非图片原件不进交付，仅在备份目录留存。

字段原则：

- `官网`、`置信度`、`pages`、`home_text` 等是抓取证据；`置信度` 为 `高（自动发现）` 时可自动采用，`中（自动发现，需复核）` / `低（自动发现，需复核）` 必须经复核表确认后才能采集，未复核的企业默认跳过且不生成 `raw`；
- `products`、`product_details`、`intro_paragraphs`、`主要业务`、`产业`、`地址` 是加工结果；
- `product_details` 只收录官网或用户资料真实给出的中文简介；只有产品名/型号/分类/系列名、没有独立描述时不要编造，对应 `产品清单.xlsx` 的 `产品详情` 单元格留空，并在 `企业说明` 页记录真实详情覆盖数；
- `product` 图片记录用于生成产品清单的 `图片（本地连接）` 列：按图片 `alt` 匹配产品名，写 `2.企业产品图/<文件名>` 相对路径；没有匹配图片的产品该单元格留空，不写占位文字；
- 抓不到官网时 `status: no_website`，四类图片全空时 `status: empty_images`；
- 有错误或简介不足三段时通常标记为 `partial`。

## 英文 JSON

`build/<run_id>/en.json` 是英文层。结构：

```jsonc
{
  "示例科技有限公司": {
    "英文名": "Example Technology Co., Ltd.",
    "英文标题": "Example Technology Co., Ltd.",
    "品牌": "Example",
    "英文简介": ["英文段1", "英文段2", "英文段3"],
    "产品英名": {"产品A": "Product A"},
    "产品详情英": {"产品A": "Product A description in English."},
    "子品类": "食品",
    "定稿": false,
    "自动翻译": true,
    "翻译引擎": "MyMemory",
    "翻译时间": "2026-10-07T12:00:00",
    "翻译失败": false,
    "备注": "英文为自动翻译草稿，待人工核校"
  }
}
```

不提供 `--en` 时默认自动中译英；`自动翻译: true` 表示机翻/模型草稿，`定稿: true` 表示人工确认稿。`英文简介` 非空即写入 docx 英文段；`产品详情英` 只翻译非空中文详情，按产品名配对并写入 `产品清单.xlsx` 的 `产品详情` 列；来源无详情时中文和英文都留空。产品图片本地链接不进入英文 JSON，直接从 raw `product` 生成。用户提供确认后的英文文件时，通过 `--en <json>` 覆盖；MyMemory 限流导致自动翻译失败时，Codex 可基于中文事实生成英文草稿并同样通过 `--en <json>` 传入，但必须保留 `定稿: false`、`自动翻译: true`、`备注: 待人工核校`，不得冒充人工定稿。

自动翻译失败、英文名为空、简介不足三段、产品或非空产品详情缺英文时，`english_backlog()` 会写 `<run_id>/英文补译清单.json`；来源无详情导致的空单元格不算英文缺口。默认门禁按 error 阻断发布。`manifest.json` 同步记录 `english_mode`、`english_backlog` 和 `accept_no_english`。只有用户在当次对话中明确接受中文版时，才可设置 `accept_no_english: true`，此时英文相关门禁降为告警但仍保留缺口记录。

## 视觉核对 JSON

`build/<run_id>/视觉核对.json` 是视觉核对结论，`gates.py --visual` 读取：

```jsonc
{
  "_说明": "结论可填 符合/不符/待核对……",
  "示例科技有限公司": {
    "图片": {
      "2.企业产品图/01_prod.jpg": {
        "结论": "不符",
        "说明": "实际是车间照片",
        "trust": "官网",
        "必核": true,
        "sha256": "当前图片内容指纹（脚本写入）",
        "reviewed_at": "结论回写时间（脚本写入）"
      }
    },
    "文档": {"结论": "符合", "说明": ""},
    "产品清单": {"结论": "符合", "说明": ""}
  }
}
```

- 键名规则：`图片` 用 `<交付分类目录>/<文件名>`，分类目录是 `1.企业工厂图` 等中文目录名。
- 结论值：`符合` / `不符` / `待核对`；空值等同待核对。
- 只认逐张 `图片` 结论，不支持类别继承；旧式 `类别` 节点会被忽略。
- 官网抓取图（`trust: 官网`、`必核: true`）必须逐张回写结论；用户资料图（`source: 用户资料`）直通，但“不符”仍 error。两者结论都只认与当前图片 sha256 匹配且带 reviewed_at 的记录。
- 该文件由 `visual_review.py` 初始化；重跑时仅保留 sha256 未变化的旧结论，图片变化会清空并重新核对。
- 它是派生结论，不改变 raw 事实；修正结论或补图后重跑门禁。

## 交付目录

每家企业：

```text
<企业名>/
├── 1.企业工厂图/
├── 2.企业产品图/
├── 3.企业logo/
├── 4.资质证书/
├── 5.企业介绍/<企业名>.docx（文件名必须与企业文件夹名一致）
└── 产品清单.xlsx
```

另有 `review/<企业>/图片核对表.xlsx`（含结论下拉、SHA256、信任层级）与 `review/视觉核对图/<企业>/*.png` 作为人工/视觉核对材料，不进交付目录。

企业文件夹内只允许上述五个文件夹和 `产品清单.xlsx`；五个文件夹内只放直接文件，不得再嵌套子目录（`structure` 门禁强制检查）。

交付目录是 `raw` + `en.json` 的派生品，不应单独手工编辑后再当作事实源；`docx_source`、`product_rows` 门禁会检查这一点。

## 状态

| 状态 | 含义 | 交付动作 |
|---|---|---|
| `ok` | 页面、图片和中文简介基本齐备 | 进入正常复核 |
| `partial` | 页面错误或中文简介不足三段 | 列入待补抓 |
| `empty_images` | 四类图片全空 | 必须在交付说明中列出 |
| `no_website` | 用户提供/人工确认的官网不可访问且无可用用户资料 | 保留档案和错误，必要时由用户补官网或资料 |
| `resource_only` | 官网未确认或不可访问，但用户资料可用 | 仅凭用户资料成档，正常进入复核；`site_discovery` 降为告警 |
| `skipped` | 官网自动发现置信度为中/低且未复核，或复核决定为跳过 | 不进入 `raw`/`deliverable`；写入 `<run_id>/官网复核结果.json`，等待复核后重跑 |
